# Glossário do produto

Status: linguagem inicial consolidada para orientar as especificações do Kaizen.

| Termo | Significado neste contexto |
| --- | --- |
| Kaizen | Sistema web para acompanhar estudo e demonstração prática de competências. |
| Ponto focal | Proponente que orienta as decisões do projeto e será o usuário da primeira versão. |
| Área de atuação | Campo de conhecimento acompanhado, como Desenvolvimento Frontend. |
| Roadmap de aprendizado | Percurso de uma área. A primeira versão terá um roadmap por área. |
| Fase de aprendizado | Agrupamento ordenado de tópicos no roadmap. As fases iniciais são Base, Profissional e Especialização. |
| Tópico | Grande bloco do roadmap, como HTML e CSS, pertencente a uma fase. |
| Conteúdo ou assunto | Item individual a estudar e praticar dentro de um tópico. É a unidade dos contadores de checklist. |
| Checklist de estudo | Lista em que o usuário marca os conteúdos estudados. |
| Progresso de estudo | Percentual dos conteúdos marcados como estudados no tópico, fase ou roadmap. |
| Cobertura prática | Percentual de conteúdos com prática validada por pelo menos um projeto concluído, contando cada conteúdo uma vez. |
| Conclusão de um tópico | Requer conteúdos cadastrados, checklist completo e prática validada de todos os conteúdos. |
| Competência | Conhecimento ou habilidade estudada e demonstrada na entrega prática. |
| Tenho Dificuldade | Avaliação pessoal que identifica um conteúdo em que o usuário percebe dificuldade. |
| Tenho Facilidade | Avaliação pessoal que identifica um conteúdo em que o usuário percebe facilidade. |
| Não avaliado | Ausência de avaliação de facilidade ou dificuldade; o preenchimento é opcional. |
| Projeto prático | Entrega relacionada a um roadmap, com conhecimentos necessários, conteúdos abordados e critérios de conclusão. |
| Conhecimentos necessários | Preparação recomendada para realizar o projeto. Orienta o percurso sem exigir que o tópico já tenha conclusão prática. |
| Conteúdos abordados | Itens cadastrados que o projeto pretende demonstrar; definem quais práticas sua conclusão pode validar. |
| Resultado esperado | Entrega ou comportamento demonstrável que o projeto deve alcançar. |
| Critério de conclusão | Item verificável do resultado esperado, marcado pelo usuário durante o projeto. |
| Projeto concluído | Projeto com todos os critérios cumpridos e confirmação manual do resultado demonstrado. |
| Prática validada | Conteúdo vinculado a pelo menos um projeto cuja conclusão foi confirmada pelo usuário. |
| Demonstração | Exemplo ou imagem usado para comunicar uma intenção de estudo ou de trabalho. |
| Catálogo inicial de projetos | Quatro exercícios progressivos recebidos do ponto focal, com fases, conhecimentos e resultados esperados. |
| Fase de referência do projeto | Nível de conhecimento indicado no catálogo: Base, Profissional ou Especialização. Orienta a escolha da prática. |
| Stack de estudo | Tecnologias recomendadas para o aprendizado; as escolhas de implementação do Kaizen serão documentadas na arquitetura. |
| MVP | Primeira entrega com organização dos estudos e acompanhamento da prática. |
| Roadmap de entregas | Planejamento da evolução do produto, registrado em [roadmap.md](roadmap.md). |

## Terminologia da referência atual

A captura chama o contador geral de 169 itens de “tópicos”. No Kaizen, os grandes blocos são tópicos e os itens individuais são conteúdos. Os números da captura representam o exemplo de uso atual.

Base, Profissional e Especialização serão adotados como fases iniciais, conforme a [organização dos estudos](visao-produto.md#organização-dos-estudos). O cálculo e a conclusão seguem a [visão do produto](visao-produto.md#cálculo-do-progresso).
